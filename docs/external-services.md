## Setup notes

### Neon
1. Create project (region close to the Render region, e.g. both in EU-Central/Frankfurt or both in US-East).
2. Copy **two** connection strings: pooled (host contains `-pooler`) → `DATABASE_URL`; direct → `DIRECT_URL`. Both with `?sslmode=require`.
3. Prisma 7: the app connects with `DATABASE_URL` through the `@prisma/adapter-pg` driver adapter (`PrismaService`); the CLI (`migrate deploy`, `studio`) reads `DIRECT_URL` from `apps/api/prisma.config.ts`. There is no `url`/`directUrl` in `schema.prisma` any more.
4. Run migrations and seed **from your machine** once: `pnpm db:migrate:deploy && pnpm db:seed` with prod env.

### Render
The service is described in [`render.yaml`](../render.yaml) (Blueprint): build/start commands, health check, region, env var names.
1. Dashboard → **New → Blueprint** → connect the GitHub repo → it detects `render.yaml` → service `shelfwise-api` (free, Frankfurt).
2. Fill the `sync: false` variables when prompted: `DATABASE_URL` (Neon pooled), `DIRECT_URL` (Neon direct), `ENABLE_DEBUG_ROUTES` (`true` during the SSE spike, then `false`), `ADMIN_EMAIL` / `ADMIN_PASSWORD`. Variables added to `render.yaml` after the Blueprint was created must be added in the dashboard by hand (Environment tab) if they are `sync: false`.
3. Deploys come from `main` only, and only after the CI check is green (`autoDeployTrigger: checksPass`). Pushes that don't touch the API (`buildFilter`) don't redeploy it.
4. Migrations and the users seed run on every start (`prisma migrate deploy && node dist/seed/run-seed-users.js && node dist/main.js`) because the free plan has no pre-deploy hook or shell; both are idempotent.
5. Build uses `pnpm install --prod=false`: with `NODE_ENV=production` pnpm would otherwise skip devDependencies (Nest CLI, TypeScript, Prisma CLI) and the build fails.
6. `JWT_ACCESS_SECRET` is generated by Render (`generateValue: true`). Rotating it logs everyone out within 15 minutes (access tokens), refresh tokens keep working.

### Vercel
[`apps/web/vercel.json`](../apps/web/vercel.json) sets install/build commands for the monorepo (installs at the workspace root, builds `@shelfwise/web` and its dependency `@shelfwise/shared`).
1. **Add New → Project** → import the repo → **Root Directory `apps/web`** → Framework Next.js.
2. Env vars (Production + Preview) **before the first deploy** — the `/api/*` rewrite destination is baked in at build time:
   - `API_ORIGIN=https://<api>.onrender.com`
   - `NEXT_PUBLIC_SITE_URL=https://<project>.vercel.app`
   - `ENABLE_EXPERIMENTAL_COREPACK=1` — makes Vercel use the exact pnpm version from `packageManager`.
3. Settings → Git → **Production Branch `main`**. `develop` and PRs get preview deployments.
4. Changing `API_ORIGIN` later requires a redeploy.
5. Later (auth step): set `WEB_ORIGIN` on Render to the Vercel URL (used by the API's Origin check).

### Uptime pinger
- UptimeRobot → HTTP(s) monitor → `https://<api>.onrender.com/health` → interval 5–10 min.
- Ping the **API's own URL**, not the Vercel rewrite (fewer hops, doesn't count against Vercel).
- `/health` does not touch the DB, so Neon still suspends when idle (saves compute hours).

### Open Library
- No account. Set `OPEN_LIBRARY_CONTACT` (your email or repo URL) — used in the `User-Agent`. Keep it out of the repo if it's personal (env var).
- Endpoints used: `/subjects/{subject}.json`, `/works/{olKey}.json`, `/authors/{key}.json`, `/search.json`, covers `https://covers.openlibrary.org/b/id/{coverId}-{S|M|L}.jpg`.

### Google AI Studio (Gemini)
1. Create an API key in Google AI Studio.
2. **Do not link a billing account** to the key's Google Cloud project — this is what makes the provider-side spend limit $0. (Google Cloud *budgets* only alert, they don't cap spend; staying on the free tier is the actual hard limit.)
3. Pick the cheapest current Flash / Flash-Lite model that supports function calling → `AI_MODEL`.
4. Read its free-tier limits (RPM, RPD) → set `AI_GLOBAL_DAILY_REQUESTS` to ~70% of RPD.
5. Key goes only into Render env and your local `apps/api/.env`.

## Environment variables

### `apps/api`

| Variable | Required | Example / default | Notes |
|----------|----------|-------------------|-------|
| `NODE_ENV` | yes | `development` / `production` | toggles `Secure` cookies, log format |
| `PORT` | no | `4000` | Render sets `PORT` |
| `DATABASE_URL` | yes | `postgresql://postgres:postgres@localhost:5432/shelfwise` | pooled URL in prod |
| `DIRECT_URL` | yes | same as above locally | direct URL in prod, for migrations |
| `JWT_ACCESS_SECRET` | yes | ≥ 32 random chars | HS256 key for access JWTs. Render: `generateValue` in `render.yaml`; locally any 32+ chars |
| `ALLOWED_ORIGINS` | prod | `https://shelfwise-khaki.vercel.app` | comma-separated; allowed `Origin` for mutating requests (CSRF check). Defaults to `http://localhost:3000` outside production |
| `TRUST_PROXY_HOPS` | no | `1` | Express `trust proxy`: which `X-Forwarded-For` entry is the client IP (rate limiting). Check with `GET /health/client-ip` (debug route) |
| `AUTH_THROTTLE_PER_MINUTE` | no | `10` | per-IP limit on `login` / `register` / `demo` |
| `SIGNUP_THROTTLE_PER_HOUR` | no | `5` | per-IP limit on `register` |
| `LOG_LEVEL` | no | `info` | `silent` in tests (set by Vitest config); `pino-pretty` output in development |
| `ADMIN_EMAIL` / `ADMIN_PASSWORD` | seed only | — | both or neither; the users seed (runs on every start) creates the admin if absent, never overwrites the password, never promotes an existing non-admin account with that email (warns instead). Password ≥ 12 chars. Set it **before** the API is publicly reachable with registration |
| `OPEN_LIBRARY_CONTACT` | yes | email or repo URL | in `User-Agent` |
| `AI_ENABLED` | no | `true` | kill switch |
| `GOOGLE_GENERATIVE_AI_API_KEY` | if AI enabled | — | AI Studio key |
| `AI_MODEL` | if AI enabled | a current Gemini Flash / Flash-Lite id | |
| `AI_MAX_OUTPUT_TOKENS` | no | `800` | |
| `AI_DAILY_REQUESTS_PER_USER` | no | `20` | |
| `AI_DAILY_REQUESTS_DEMO_USER` | no | `100` | shared demo account total |
| `AI_DAILY_REQUESTS_DEMO_PER_IP` | no | `5` | |
| `AI_GLOBAL_DAILY_REQUESTS` | no | `500` | keep below provider RPD |
| `IP_HASH_SALT` | if AI enabled | random | hashing IPs for `AiIpUsage` |
| `ENABLE_DEBUG_ROUTES` | no | `false` | enables `GET /health/stream?seconds=N` (SSE spike, max 120s) and `GET /health/client-ip`; keep `false` in production except while diagnosing |
| `CRON_SECRET` | optional | random | nightly demo reset |
| `TEST_DATABASE_URL` | tests | `postgresql://postgres:postgres@localhost:5433/shelfwise_test` | e2e |

### `apps/web`

| Variable | Required | Example | Notes |
|----------|----------|---------|-------|
| `API_ORIGIN` | yes | `http://localhost:4000` | server-only: rewrites, middleware, RSC fetches |
